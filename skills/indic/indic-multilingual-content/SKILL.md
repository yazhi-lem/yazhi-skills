# Indic Multilingual Content

Multiple Indian languages in one product are not multiple copies of English. This skill owns the cross-language content workflow: intent, register, code-mixing, and consistency across locales. Language-specific craft stays with `tamil-content-writing`, `tamil-tani-tamil`, and their siblings.

## Workflow

1. **Write a language-independent brief first.** State the audience, purpose, claim, and call to action once. If the English brief contains culture-specific examples, mark them for replacement rather than translation.
2. **Draft in each language from the brief.** Original-language drafting beats literal translation. Use `tamil-content-writing` for Tamil, and require a native speaker for every other target language before shipping.
3. **Set one register map.** Decide per locale whether the voice is formal, familiar, or youth-led; use the same scale across all languages so one locale does not sound like a different product.
4. **Treat code-mixing as a choice.** Hinglish, Tanglish, and region-specific mixing are normal. Decide per surface whether to allow it, and record the rule; do not let an auto-translator invent it.
5. **Replace, do not translate, culture-bound examples.** Festivals, food, school references, and humor need local equivalents with the same role in the sentence. A literal reference that a reader does not recognize is noise.
6. **Check claims across languages.** A number, law name, or product term must mean the same thing in every version. Keep a glossary of approved terms and route technical coinages through `tamil-technical-terms` where Tamil is involved.
7. **Review as a batch.** Compare all versions side by side for hook, CTA, specificity, and tone before publishing. Record the reviewer per language; "machine-fluent" is not native review.

## Locale review table

| Check | Evidence | Failure signal |
|---|---|---|
| Meaning | Brief and claim match in every language | One version promises something others do not |
| Register | Same scale applied across locales | One version reads like a press release, another like a chat |
| Code-mixing | Rule recorded per surface | Mixed language appears accidentally in formal copy |
| Culture | Examples replaced, not translated | Unrecognized festival/food reference |
| Terms | Shared glossary | Same concept has three names in one campaign |
| Reviewer | Named native speaker per language | Only the source language was reviewed |

## Anti-patterns

- **Translating English strings as the default workflow.** It carries English syntax and idiom into languages that do not use them.
- **Using one reviewer for all languages.** Fluency in one language does not certify another.
- **Mixing languages without a rule.** Accidental code-switching reads as carelessness; intentional mixing reads as audience awareness.
- **Keeping culture-bound examples unchanged.** A locally meaningless example weakens the claim instead of illustrating it.
- **Publishing versions at different times without re-check.** A later edit in one language breaks the batch consistency.
